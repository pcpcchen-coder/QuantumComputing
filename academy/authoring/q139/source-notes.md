- 【推論】假設：「可調耦合器 | 約 1.5 N（方格約 2 N、heavy-hex 約 1.2 N，取中間）| 1,500」；「每條讀取饋線的位元數 | 8（文獻常見 5–10 個……）| 125 條饋線」；「脈衝管數量 | 3（每個稀釋單元 1 支；KIDE 實際數量未公開）」

- 「XY 驅動線 | 1,000 | 每位元 1 條」「磁通（Z）線 | 2,500 | 位元 1,000＋耦合器 1,500」「讀取輸入 | 125 | 每 8 位元 1 條」「讀取輸出 | 125」「TWPA 泵浦 | 125」

## animations/power1000.html（場景 2：規模計算器，約第 251–297 行；共用模型約第 75–100 行）

- 標題／sub：「規模計算器：位元數一變，什麼先爆？」「推論模型：可調耦合器 1.5 N、每饋線 8 位元、KIDE 級冷凍機 4,000 條線」
- desc：「切換成『低溫 CMOS＋多工』：進入冷凍機的線大幅減少（假設減為 1/16），但 4 K 要多出每位元約 1.5 mW 的熱負載，而且需要低溫電源轉換。」「紅色代表超過門檻。」
- 控制項：`slider('量子位元數 N', 2, 4.3, 0.01, 3, v => fmtN(Math.round(10 ** v)), …)`、`slider('每位元室溫控制電子功耗', 1, 150, 1, 50, v => v + ' W', …)`、
  `select('架構', [['rt', '今日：室溫控制、每位元獨立線'], ['cryo', '未來：低溫 CMOS＋多工']], 'rt', …)`
- lines()：`const C = Math.round(1.5 * N), fl = Math.ceil(N / 8); const xy = cryo ? Math.ceil(N / 16) : N; const flux = cryo ? Math.ceil((N + C) / 16) : N + C; … total: xy + flux + 3 * fl, dc: (cryo ? 0 : N + C) + 3 * fl`
- heat()：`r.s4 += L.fl * 1e-3; // HEMT 約 1 mW（中間值）`、`if (o.cryo) r.s4 += o.N * 1.5e-3; // 低溫 CMOS 每位元 1.5 mW（假設）`；`CAP = { s50: 52.5, s4: 1.9, … } // 每支脈衝管／每個稀釋單元`
- render()：`const fridges = Math.max(1, Math.ceil(L.total / 4000)); const pts = Math.max(3 * fridges, Math.ceil(H.s50 / CAP.s50), Math.ceil(H.s4 / CAP.s4));`
  `const elec = st.N * (st.cryo ? Math.min(st.W, 5) : st.W) / 1000, comp = pts * 12.5; const dec = st.N / 1000 * 25, hv = 0.4 * (elec + dcUnits * 0.045 + dec); const kw = comp + 0.6 * comp + 4 * fridges + elec + dcUnits * 0.045 + 3 + dec + hv;`
- 列門檻：同軸 4000（`需 ${fridges} 台 KIDE 級`／`1 台 KIDE 級內`）、精密直流 3000、交流入口 350、地線 0.1、脈衝管 5、4 K `CAP.s4 * pts`、設施 320。
- 顏色：`fill: bad ? '#ff5a5f' : frac > 0.75 ? '#e0a54a' : '#38c6d9'`；4 K 列 `bad = val > ref`，且不畫白色虛線；底部文字「虛線＝門檻（1,000 位元參考值）」。

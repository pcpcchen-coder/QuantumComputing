## 如何操作量子電腦（slides/QC_Operation_Talk.pptx）

第 42 頁「快在哪？加速的等級」
- 表格：「無結構搜尋 / O(N) / O(√N) / 平方」「蒙地卡羅估計 / O(1/ε²) / O(1/ε) / 平方」「質因數分解 / 離散對數 … 超多項式（指數級）」
- 「平方加速：差距是 N 和 √N，好處要在 N 很大時才顯現，而且容易被量子閘較慢、錯誤更正的開銷吃掉」
- 「實際比較要算總時間：shots、錯誤更正、資料載入」
- 講者備註：「指數級加速是質的差別」「注意右圖的縱軸是對數…這張圖只是示意趨勢，常數都略去了」

第 43 頁「為什麼古典電腦模擬不了？」
- 「2019 Google Sycamore（53 位元）隨機線路取樣：200 秒（後續古典演算法大幅追近）」
- 「→ 優勢邊界持續被古典演算法挑戰」

第 44 頁「量子電腦能算什麼：應用地圖」
- 「密碼分析（RSA、ECC）/ Shor / 指數級 / 需容錯；RSA-2048 估計 < 100 萬實體位元、< 1 週（2025）」
- 「化學、材料、藥物 / … / 指數級（多數）/ 小分子已示範；工業級分子需數百萬實體位元等級」
- 「物理模擬（自旋、凝態）/ 哈密頓模擬 / 指數級 / 最可能最早實用；已有超越古典的實驗」
- 「金融、風險評估 / 振幅估計 / 平方 / 需容錯；常數開銷大」
- 「最佳化 / QAOA、量子退火、Grover 類 / 啟發式 / 平方 / 實用優勢尚未確立」
- 「機器學習 / 量子核方法、HHL 類 / 未定 / 資料載入是瓶頸；仍在研究」
- 註：「資源估計：Gidney, arXiv:2505.15917（2025）；其餘為文獻常見結論，依技術進展會變動」

第 45 頁「哪些事不會變快」
- 「把 N 筆資料載入量子態通常要 ~N 步；沒有實用的 QRAM → 大數據分析難以加速」
- 「n 個量子位元只能讀出 n 位元；想要整個向量就要指數次量測」
- 「加減乘除、排序、資料庫查詢、渲染、文書：沒有已知的量子加速」
- 「量子閘 ~100 ns、錯誤更正開銷大；問題不夠大時古典更快」
- 「精度 ε 需要 ~1/ε² 次（或振幅估計 ~1/ε 次）重複」
- 「結論：最適合量子電腦的問題是『輸入小、計算難、輸出小』，而且有可利用的數學或物理結構」

## animations/js/operation/09_grover.js

- subtitle：「在 N 個候選中找出標記的答案：古典平均 N/2 次，量子約 (π/4)√N 次」
- desc：「加速是平方級：N = 100 萬時，古典平均 50 萬次，Grover 約 785 次。」「轉太多次反而會轉過頭！」
- `const kOpt = () => Math.max(1, Math.round(Math.PI / (4 * theta()) - 0.5));`，`theta = asin(1/√N)`
- `ui.slider('量子位元數 n', 2, 6, 1, n, …)`，預設 `n = 4`；按鈕「自動跑到最佳次數」：`setup(); autoRun = true`，每 0.8 s 一步
- inset「幾何圖：每輪在『答案–非答案』平面轉 2θ」，右半「P(成功) vs 輪數」
